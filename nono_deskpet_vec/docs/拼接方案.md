# NONO 桌宠 · 分层矢量拼接方案（定稿记录）

日期：2026-10-24
代号：20261024-09
状态：方案已定，开始实施

---

## 0. 一句话

把 NONO 从「SWF 烘焙成 169MB PNG 整帧」改成「自定义分层矢量 JSON + Go 运行时合成」，
SWF 只做一次性导入源，之后新增形态/表情完全不碰 Flash。

---

## 1. 为什么换

现有链路的问题（都是"把矢量烘焙成位图"造成的）：

| 现象 | 根因 |
|---|---|
| 17 帧里第 8 帧掉脸/变形 | 嵌套 MC 时间轴未全部钉住（desc 递归不足） |
| up/right 方向多出别的方向的白色弧 | 漏解析 RemoveObject2，跨段串层 |
| 画布被 super4 长鳍撑到 571×430，大半透明 | 整帧烘焙只能取并集 bbox |
| DPI 125%/150% 发虚 | 4x 预烘，超出即重采样 |
| 改一个表情要重烘整套帧 | 烘焙粒度是整帧 |
| 打包 169MB | PNG 帧 |

以上问题在矢量结构下**不存在**，不是"修好了"，是"没有这个概念"。

## 2. 数据格式（format: 1）

### 2.1 形态文件 `assets/sprites/<form>/sprite.json`

```json
{
  "format": 1,
  "name": "plain",
  "canvas": { "w": 118, "h": 132, "anchor": [59, 74] },
  "colors": { "shell": "#FFFFFF", "glow": "#2A9FD4", "inner": "#1B1B1B" },
  "layers": [
    { "name": "color_2", "z": 0, "tintable": true },
    { "name": "body",    "z": 1, "tintable": false },
    { "name": "color_1", "z": 2, "tintable": true }
  ],
  "directions": {
    "down": { "frames": [ { "parts": [ ... ] }, ... ] },
    "leftdown": { "frames": [ ... ] },
    "left": { ... }, "leftup": { ... }, "up": { ... },
    "rightup": { ... }, "right": { ... }, "rightdown": { ... }
  }
}
```

帧内一个 part：

```json
{
  "layer": "body",
  "part": "parts/body_down.json#face",
  "matrix": [1, 0, 0, 1, 0, 0],
  "fill": "#1B1B1B",
  "alpha": 1.0
}
```

### 2.2 部件文件 `parts/*.json`

```json
{
  "id": "shell_up",
  "paths": [
    {
      "d": "M25.3 11.9 Q25.0 15.95 27.3 23.6 ...",
      "fillRule": "evenodd",
      "stroke": { "color": "#1A1A1A", "width": 1.5, "cap": "round", "join": "round" }
    }
  ]
}
```

`d` 用 SVG path 语法（M L H V Q C Z + 相对形式），任何矢量工具都能出。

### 2.3 表情/动作 `assets/sprites/<form>/overrides/*.json`

```json
{
  "id": "smile",
  "duration": 1200,
  "overrides": [
    { "layer": "body", "slot": "mouth", "part": "parts/mouth_smile.json" }
  ]
}
```

### 2.4 设计约束

1. **时间轴扁平**：形态 → 层 → 方向 → 帧 → 部件。不允许嵌套 MC。
2. **部件复用**：几何放 `parts/`，多个形态/表情共享。
3. **颜色槽位**：`colors` + part 的 `fill` 引用槽位名，染色只改槽位值。
4. **锚点内置**：`canvas.anchor` 就是球心，不再需要 measure_ballc 反推。
5. **format 版本号**：新增字段不破坏旧文件，加载器按版本兼容。

## 3. 渲染架构

```
sprite.json + parts/*.json
   │  加载 + 校验（format/必填字段/引用存在）
   ▼
IR（path 已解析成线段+贝塞尔，矩阵预乘，按层分组）
   │  按 (方向, 帧) 取 part 列表
   ▼
合成器
   │  z 排序 → 逐 part 光栅化（fill + stroke，4x 超采样）→ 下采样
   ▼
*image.RGBA（与现有 FrameSet 输出同类型）
   │
   ▼
现有 blit / 窗口 / 穿透 / 交互（不改）
```

### 3.1 渲染后端接口

```go
type Sprite interface {
    SetDirection(dir string)
    SetFrame(i int)
    SetTint(layer string, rgb uint32)  // 对应原版 FillColor
    Bounds() Rect                       // 实时，替代 ball_anchor
    Render(dst *image.RGBA, scale float64)
}
```

`assets.go` 的 `FrameSet` 内部换实现，上层零改动。

### 3.2 技术选型

| 环节 | 选择 | 理由 |
|---|---|---|
| path 解析 | 自写（M/L/H/V/Q/C/Z） | 不引第三方，语法有限 |
| 光栅化 | `golang.org/x/image/vector` | 准标准库，抗锯齿 + even-odd |
| 描边 | 自写 stroker（折线 + 圆角关节） | 无现成库；NONO 线宽 1~2px，圆角足够 |
| 超采样 | 3~4x 渲染后 Lanczos 下采样 | 对标 Flash 4x 抗锯齿 |
| 缓存 | 按 (form, dir, frame, tint, scale) 缓存位图 | 避免每帧重算 |

## 4. 以后怎么改

### 4.1 新增形态
复制 `super5/` → 改 `sprite.json` 的 `colors` 和 part 引用 → 重启生效。

### 4.2 新增表情
加一个 `overrides/smile.json`，指定替换哪个 slot 的 part。

### 4.3 美术画新部件
Figma/Illustrator/Inkscape 导出 SVG → `tools/svg2part` 抽出 `<path d>` → 写进 `parts/*.json`。

### 4.4 批量生成
形态参数化（球径、耳长、鳍形、配色）→ 脚本生成 JSON。

### 4.5 开发期热重载
`--reload` 监听 JSON 变化，改完立即看到，不用重新打包。

## 5. 实施阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 目录骨架 + 格式定义 + 校验器 | `vecgen validate` 通过 |
| P1 | SWF → JSON 导入器（plain 先行） | plain 3 层 8 方向 17 帧全部转出 |
| P2 | path 解析 + fill 光栅化 | down 单帧与 FFDec 渲染像素对比 <1% |
| P3 | stroke 光栅化 + 多图层 + 颜色槽位 | 8 方向 17 帧全对比通过 |
| P4 | 接入 FrameSet，桌宠跑通 | 桌宠可跑，交互不变 |
| P5 | super1~5 + 飞行 + 动作 + 表情 | 全形态对比通过 |
| P6 | 退役烘焙链，删 PNG | 打包体积 <10MB |

---

## 6. 验收标准

1. **像素**：与 FFDec 渲染同帧对比，差异像素 <1%，且差异集中在抗锯齿边缘。
2. **清晰度**：DPI 150% 下无发虚（对比现有 4x 烘焙）。
3. **体积**：源 JSON <5MB，打包 <10MB。
4. **可改性**：新增一个表情只改 1 个 JSON，不改代码、不重烘。
5. **结构正确**：不再出现跨段/串层（扁平时间轴，结构上不可能）。
