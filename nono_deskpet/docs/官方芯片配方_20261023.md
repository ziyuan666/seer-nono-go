## 这份"配方数据"到底是什么

不是坐标、不是 NPC 位置，而是**服务端的一张规则表**：三种材料道具 ID + 模板等级 → 产物道具 + 成功率。

外部参考服务端的数据结构（`internal/handlers/weights.go:23-36`）：

```go
type ChipMixtureRule struct {
	Mat1, Mat2, Mat3 int  // 三个材料道具 ID（可相同）
	SuccessRate      int  // 成功率 0-100
	RewardItemID     int  // 产物道具 ID
	RewardCount      int  // 数量
}
```

9004 请求包是 `mixId(模板) + count + [itemId+num]*count`，服务端把三个材料 ID 排序后跟规则匹配，命中就按成功率给产物。外部参考服务端里 `ChipMixtureRules` 默认是**空数组**，所以任何组合都匹配不到、返回 0——这就是"配方数据缺失"的含义。

### 与官方的已知偏差

- 官方合成消耗「赛尔豆 + AI 门槛」，桌宠折算为能量 30/50/80，AI 门槛不校验。
- 官方材料靠挖矿/采集/任务，桌宠预置且**无限使用**（`20261023-15`）；官方模板耗赛尔豆，桌宠折算能量。
- 原版左右翻页箭头翻 4 枚图标；桌宠改为材料选择菜单（12 种一屏）。

## 来源可信度

- 两份攻略来自 2009-11 与 2010-05，都是公测早期，覆盖的正是 9023 那 12 枚芯片的年代，可信度高。
- 但**成功率**没有任何公开资料，官方表里这一列只能靠猜或全部设 100。
- 「星球测绘」只列了两种材料，与原版三材料槽不符，可能是资料漏写或该项只用两格。
