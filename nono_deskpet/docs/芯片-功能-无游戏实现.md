## 二、为什么后 5 枚彻底没反应

### 2.1 唯一的输出是文字，而文字被关掉了

`main.go:2266`（2026-10-27 按子渊要求改的）：

```go
// 使用芯片不再弹气泡（2026-10-27 子渊）：颜色、能量、智能的变化本身就是反馈。
// 只有「取色被取消、什么都没改」才提示一句，否则用户会以为程序没响应。
if msg != "" && strings.Contains(msg, "保持原样") {
    g.setBubble(msg)
}
```

- 颜色 / 能量 / 智能类芯片：变化本身可见，关掉气泡合理。
- `scan` / `radar` / `talk` / `sort`：**唯一的输出就是那句 msg**，气泡一关就完全静音，观感等同「点了没反应」。

### 2.2 原版依赖游戏侧系统，桌宠没有对应载体

| 芯片 | 原版作用 | 桌宠缺什么 |
|---|---|---|
| 星球测绘 | 星球地图 / 资源分布 | 没有地图系统、没有星球数据 |
| 雷达 | 侦测附近精灵 / 玩家 | 没有精灵实体、没有服务端 |
| 精灵翻译 / 初级语言 | 翻译精灵对话 | 没有 NPC 对话系统，只剩本地台词池 |
| 经验加成 | 经验获取加成 | 桌宠没有真正的经验产出流程，`ExpBonus` 无消费方 |
| 技能排序 | 精灵技能排序 | 没有精灵/技能数据 |

## 三、可选的三种处理

| 方案 | 做法 | 代价 | 影响 |
|---|---|---|---|
| **A. 修反馈** | 给「纯文本型」effect（`scan`/`radar`/`talk`/`sort`）恢复一次气泡，其余保持不弹 | 约 5 行，一处判断 | 点下去有回应，但内容仍然是占位文案 |
| **B. 收口菜单** | 把无反馈的从右键菜单过滤掉 | 改 `menuHiddenChipIDs` 一处 | 界面干净，但芯片仍在储藏/资料面板里显示，界面与功能不一致 |
| **C. 真做功能** | 星球测绘弹小地图、雷达扫屏幕窗口、翻译按场景出话 | 面板级工作量 | 真正填补原版空白 |

当前采取：**未改任何功能实现**，仅把「机械臂」从右键菜单移除（它的效果就是玩球，且芯片默认已加载）。
