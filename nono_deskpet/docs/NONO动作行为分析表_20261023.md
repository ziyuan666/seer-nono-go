## 0. 一句话结论

NONO 不是一个"会自己动的 NPC"，而是**挂在赛尔模型（ActionSpriteModel）下的一个子显示对象**：位置、朝向、层级全部由赛尔驱动，动作/表情/声音由 `NonoModel` 的定时器 + SWF 内嵌循环帧组成，所有远程指令都走 9xxx 协议经 `NonoManager.dispatchAction` 分发。

状态机主轴：

```
[无NONO] --9001开通--> [有NONO/关机态] --开机(action2)--> [待机]
   │                                                      │
   │                                        ┌─────────────┼─────────────┐
   │                                   独立态(在家)   跟随态(召唤)   飞行态(载具)
   │                                  自动游走+表情   贴赛尔+表情   赛尔被抬高
   └──9019=0 回家 / 9019=1 召唤 / 2112 飞行切换 / 9014 开关机 / 9016 续费
```

|---|---|---|---|---|---|---|---|

| `super/action/`（超能 1-5） | 只有 1_1、1_2 | 2_1~2_5 | 3_1~3_5 | 4_1~4_5 | **5_1~5_4（缺 5_5）** | 6_1~6_5 | 7_1~7_5 |
| `annual/action/`（至尊年费） | ❌ | ✅ | ✅ | ✅ | ❌ | ✅ | ✅ |

动作播放链（`onResAction()` :419-457）：

1. `clearActionMC()` 清掉旧 action/exp/声音
2. 资源为空 → 直接 return（**普通 NONO 点 3/4/5/6/7 全部静默**）
3. 设 0.8 缩放、按 `color_` 前缀重新上色、加入显示
4. `stopAutoTime()`（停自动游走 + 停表情定时器）
5. 末帧挂 `onActionScript`；`gotoAndPlay(1)`；移除 `_bodyMC`
6. 有第二资源（`sou`）→ 按 `souLoops` 播声音
7. `DepthManager.bringToTop(this)`

结束判定（`onActionScript()` :457-474）：`autoEnd=1` → 发 `NonoEvent.PLAY_COMPLETE` → `_actionID=0` → 恢复 body → `initCheck()`；`autoEnd=0` → 保持不变（等待外部指令）。

## 6. 表情（exp）与台词

### 6.1 表情权重（`exp` 段）

| 形态 | id=1 开心 | id=2 生气 | id=3 惊讶 | id=4 悲哀 |
|---|---|---|---|---|
| 普通 NONO | odds=1 | 1 | 1 | 1 |
| 超能 NONO（superExp） | **odds=3** | 1 | 1 | 1 |

即：普通 NONO 四种等概率；超能 NONO 开心占 50%，其余各 1/6。

资源：`exp/1~4.swf`（普通）、`super/exp/1~4_1~5.swf`（超能全形态）、`annual/exp/1~4.swf`（至尊）。

### 6.2 台词筛选（`getLinesIDForExp` :157-203）

输入：`expID` + `_info.getPowerLevel()` + `_info.getMateLevel()`。

等级换算（`NonoInfo.as:getPowerLevel/getMateLevel`）：`≤30 → 1`，`31~69 → 2`，`≥70 → 3`。

逐条匹配 `lines` 项：`energy` 字符串包含当前 powerLevel **且** `mate` 字符串包含当前 mateLevel 才入选。

> 注意：配置里普通台词 26、27 写的是 `mate="1,2,3,4"`，而 `getMateLevel()` 最大只返回 3，所以这两句**永远不会出现**（配置遗留，不是 bug 但等同于死数据）。

### 6.3 台词样本（普通 NONO）

| id | 台词 | energy | mate |
|---|---|---|---|
| 1 | 早上好！ | 1,2,3 | 3 |
| 2 | 叭叭，叭叭… | 1,2,3 | 2 |
| 6 | 别小看我！ | 3 | 3 |
| 9 | 真想出去逛逛 | 3 | 1,2,3 |
| 12 | 好想你呀 | 1,2,3 | 2 |
| 14 | 能源不足，能源不足 | 1 | 1,2,3 |
| 24 | 要和我玩吗？ | 1,2,3 | 3 |
| 25 | 新星球呀，哇好好玩哦！ | 1,2,3 | 1,3 |

超能 NONO 有独立的 `superLines` 1~30（内容不同，例如「(*^__^*) NoNo好开心哦，一块玩吧！」「主人，我们的战队叫什么呢？」）。

### 6.4 芯片与表情的关系

**没有绑定关系。** 芯片不决定播哪个表情，只通过两条路径间接影响：

1. `UsePower` 改 `power` → 影响 `getPowerLevel()` → 影响台词池；
2. 使用能量/玩具类道具时才触发固定动作（Play=5 吃电池、Play=4 玩球、Play=7 玩魔方），这是**动作**不是表情。

### 17.24 状态字段族与默认值陷阱（改动前必读）

同一个「有没有 NONO / 是否跟随」在整条链路上有 **6 个字段**，含义并不相同：

| 字段 | 出处 | 真实语义 | 默认值 | 客户端用途 |
|---|---|---|---|---|
| `HasNono` | 2001 登录包独立字段 | 是否拥有 NONO | **新号 = 1** | `actorInfo.hasNono`：领取处、肖恩、每周五提醒、训练列表 |
| `Flag` | 9003 第 2 个 u32（32 位位图） | **非 0 = 有 NONO**；基地且跟随时服务端置 0 | **新号 = 1** | `NonoInfo.flag[]`；**`flag` 为 0 时 `NonoInfo` 构造直接 return，整个对象为空** |
| `State` | 9003 第 3 个 u32 | 状态位：`state[0]`=开机、`state[1]`=跟随 | 0 | `NonoModel.initCheck` 判开机、`RoomMachShow` 判是否在家 |
| `nonoState` | 2003 位图 | `Flag \| (State==1 ? 2 : 0)` | — | `PeopleModel` 建模时读 `bit1` 决定 `showNono` |
| `IsFollowing` | `NonoData` | 无 | false | **死字段，全工程无读写** |
| `FlyMode` | `NonoData` + 2112 | 飞行风格 0-4 | 0 | 建 `NonoFlyModel` |

三个必须知道的坑：

1. **新号默认就有 NONO**：`userdb.go:1390-1392` 里 `HasNono=1, Flag=1, State=0`。原版要完成基地任务 461 才领养，所以 外部参考服务端里 `GetNoNo` 对任何新号都直接提示「已经有 NoNo 咯」，领养流程等于废弃。
2. **`Flag=0` 不是"没跟随"，是"没有 NONO"**：9003 的 flag=0 会让客户端 `NonoInfo` 构造函数提前 return（`NonoInfo.as:56-59`），后续所有字段都不解析。基地里置 0 是为了不重复画，但这个 0 同时抹掉了 state/nick/color。
3. **别去改 `IsFollowing`**：改了没有任何效果，唯一可信状态源是 `Nono.State`。

### 17.25 基地房间里的 NONO 展示（RoomMachShow）

基地里看到的 NONO 不是 `NonoModel` 跟随态。`app/sceneInteraction/RoomMachShow.as` 单独负责：

### 17.26 事件与信息缓存

| 事件 | 触发时机 | 消费者 |
|---|---|---|
| `GET_INFO` | 9003 回包，或**缓存命中**（见下） | `RoomMachShow` 初始化、各信息面板 |
| `FOLLOW` / `HOOM` | 9019 回包（state=1 / 0） | `RoomMachShow` 销毁/重建基地那只；`FollowCmdListener` |
| `INFO_CHANGE` | 9010（芯片/道具）、9013（玩耍）回包后 | 面板刷新数值 |
| `PLAY_COMPLETE` | 动作播完且 `autoEnd=1`（带 `actionID`） | `NonoModel.onActionScript` 自身收尾 |

**信息缓存 200 秒**：`NonoManager.getInfo(false)` 距上次拉取 <200000ms 时**不发 9003**，直接把旧 `info` 派发出去；只有 `getInfo(true)` 才强制刷新（`NonoManager.as:44-64`）。所以别人在我缓存期内改我的 NONO（GM 改数值/颜色），本地最长 200 秒内看不到，除非触发重建。
